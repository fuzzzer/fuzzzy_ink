# Test vectors for `PROTOCOL.md`

Machine-generated by `rust/fuzzy_crypto_core/src/vectors.rs` and checked on every `cargo test`
(`vectors::committed_vectors_match`). Do not edit by hand: after a deliberate format change run

```
FUZZY_WRITE_VECTORS=1 cargo test --locked vectors::write_vectors     # from rust/fuzzy_crypto_core
```

which rewrites every file and asserts that a second generation is byte-identical.

## Files

- `<name>.hex` — the bytes, lowercase hex, 32 bytes per line. `xxd -r -p <name>.hex | xxd` shows them with offsets.
- `<name>.txt` — for wire blobs, the paste-able `Fuzz/` + base64url form (what a user would copy).
- `<name>.json` — every input the vector was built from (keys, seeds, salts, nonces, chat id, text) and the
  AAD/KDF rule that applies. Secrets in these files are public test constants (`01×32`, `pw`, …), never
  production material.
- `state_file.body.json` — the decrypted body of `state_file.hex`.

## What is not here, and why

vodozemac draws randomness (base key, ratchet key) inside `create_outbound_session` and `encrypt` with no
injection point, so no vector contains a real Olm message: the acceptance, the message and the chat-mode
file header carry placeholders where the Olm body goes. The Olm message encoding is vodozemac's own
(audited) format and is outside `PROTOCOL.md`'s scope; the layouts *around* it — the length prefixes, the
signed range, the header bytes that become every chunk's AAD — are what these vectors pin.
