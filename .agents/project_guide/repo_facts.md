# Fuzzzy Ink — repo facts

Project knowledge the bot collected for this repo (checks, commands, known legacy patterns,
repo facts), from its generic `.agents/README.md` + `LAWS.md` entry, which is not used here. The shared
handbook section is not copied. Where this file and this repo's own guides disagree, the repo's own
guides win.

Fuzzzy Ink (the code and the store identifier on this line still say Fuzzzy Seal, `fuzzzy_seal`,
`com.fuzzzycore.seal`): a 100% offline encryption app disguised as a chat. Flutter 3.41.7 / Dart
3.11.5 through `fvm`; every primitive lives in the Rust crate `rust/fuzzy_crypto_core` (toolchain
1.98.1) behind `flutter_rust_bridge` 2.13.0; design from `fuzzzy_ui_kit` (git, pinned ref). Entry
points: `lib/main_development.dart` (Marionette in debug), `main_staging.dart`, `main_production.dart`.
Features: `fuzzzy_seal` (pairing, chats, files), `fuzzy_auth` (app lock), `fuzzy_vault`, `fuzzy_basics`.
Every feature here is a legacy zone; the shape to copy is `fuzzy_starter` `lib/src/sample_posts/`.

Every command runs from the repo root; checks run on the committed tree, with `set -o pipefail`.
Open work items are in `.agents/workfiles/tasks/`.

## Task → what to read or do

| Task | Read | Do |
|---|---|---|
| Add a feature | `fuzzy_starter` `lib/src/sample_posts/` · the "Legacy zones" | new module in the handbook shape under `lib/src/<feature>/` → `./exp.sh` → register in `lib/src/core/dependency_injection.dart` → route in `lib/src/app/app_router.dart` → tests |
| Touch `rust/`, `lib/rust_bridge/` or `lib/src/core/encryption_services/` | `documents/security/PROTOCOL.md` · `THREAT_MODEL.md` · the "Rust core" | Rust first, then `cargo test`, then the bridge codegen; commit the generated files |
| Add a page | `lib/src/app/app_router.dart` | path constant on `AppRouter` → `GoRoute` → six states |
| Add a string | the "Localisation" | both `.arb` files, then `fvm flutter gen-l10n` |
| Add a dependency | `pubspec.yaml` · `rust/fuzzy_crypto_core/Cargo.toml` | exact version; no network package; then `./sbom.sh rust` or `./sbom.sh flutter` |
| Add a `.dart` file | the "Generators" | `./exp.sh`, then undo its two l10n side effects |
| Run checks | the "Checks" | setup first, then the commands in order; all green before review |
| Run the app | — | `fvm flutter run --flavor development -t lib/main_development.dart -d macos` (`--flavor` is mandatory) |

## Never

- Read, write or request `.env` or any secret file; signing keys live in the Codemagic UI only.
- Hand-edit a file LAWS marks "regenerated by tool" (`lib/rust_bridge/**`, `frb_generated.rs`, l10n, `*.g.dart`).
- Edit `.agents/` from a build unit: it is the repo's law.
- Add a network package (`http`, `dio`, sockets) or any server call: offline is the product.
- Write cryptography in Dart, or pass key bytes across the bridge.
- Run `flutter_rust_bridge_codegen integrate`, build with `--cfg fuzzing`, or bare `fvm dart format .`.
- Fork or vendor `fuzzzy_ui_kit`, or add widgets to the local `lib/src/ui_kit/`.

## Local law

| Id | Rule |
|---|---|
| LOCAL-1 | Offline is the product: no network package in `pubspec.yaml` or `Cargo.toml`, no HTTP, socket or remote call in `lib/` or `rust/`. Encrypted output leaves only through the user's own share sheet, files or clipboard. |
| LOCAL-2 | All cryptography lives in `rust/fuzzy_crypto_core` (pinned crates only, no hand-rolled primitive). Dart holds no key bytes, no `Random.secure`, no hash, KDF or AEAD code; a new cryptographic operation is a Rust `api/` function plus bridge codegen, never a Dart helper or a Dart crypto package. Keys cross the bridge only as opaque handles (`CryptoCore`, `VaultKey`, `FileJob`, passed by reference). |
| LOCAL-3 | Before touching `rust/`, `lib/rust_bridge/` or `lib/src/core/encryption_services/`, read `documents/security/PROTOCOL.md` and `THREAT_MODEL.md`: they are the specification. Every blob starts with `FUZZ 01 <type>`; ratchet state is persisted before a result is returned; never build with `--cfg fuzzing`; no `#[frb(sync)]` on anything touching a key, Argon2 or an AEAD. |
| LOCAL-4 | In `lib/`, only `lib/src/core/encryption_services/crypto_core_service/crypto_core_service.dart` and `lib/src/app/initializer.dart` import `package:fuzzzy_seal/rust_bridge/…`; in `test/`, only `test/helpers/crypto_core_test_init.dart` and `test/src/core/rust_bridge_smoke_test.dart`. Every core call returns `CryptoCoreResponse<T>` (`CryptoCoreSuccess` or `CryptoCoreFailure`) from `CryptoCoreService`. |
| LOCAL-5 | `package:isar` is imported only by `lib/src/core/dependency_injection.dart`, `storage_models/` and `local_data_sources/`. Isar is not encrypted: a sensitive column holds a Rust-sealed blob. |
| LOCAL-6 | `flutter_rust_bridge` moves in lockstep at `2.13.0` in three places: `pubspec.yaml`, `rust/fuzzy_crypto_core/Cargo.toml` (`=2.13.0`) and the codegen that wrote `lib/rust_bridge/`. Never run `flutter_rust_bridge_codegen integrate` (it overwrites `rust_builder/`). |
| LOCAL-7 | A dependency bump ships its SBOM in the same commit: `./sbom.sh rust` or `./sbom.sh flutter` (CI fails on drift). |
| LOCAL-8 | Marionette is initialised only in `lib/main_development.dart`, under `kDebugMode`. `--flavor` is mandatory on every run and build. Timings (unlock, Argon2id, file throughput) are measured on `--profile` or release, never debug. |
| LOCAL-9 | OS and cloud backups stay opted out on every platform; `test/platform/backup_opt_out_test.dart` pins the manifests. |
| LOCAL-10 | The format check covers `lib test` only: `rust_builder/` is vendored cargokit, `lib/rust_bridge/` is formatted by its codegen. |
| LOCAL-11 | The project import is `package:fuzzzy_seal/src/src.dart` (FZ-FLT-L4) in every new file; `package:fuzzzy_seal/lib.dart` re-exports it and is what older files use. The two sanctioned extra imports: `package:fuzzzy_ui_kit/fuzzzy_ui_kit.dart`, and `package:fuzzzy_seal/rust_bridge/…` in the files LOCAL-4 names. |

### Dependency registration
- Applies to: `lib/src/core/dependency_injection.dart`, `lib/src/*/data/**`, `lib/src/*/storage/**`, `lib/src/*/bloc/**`, `lib/src/*/ui/pages/**`
- File: `lib/src/core/dependency_injection.dart`, one static `DependencyInjection.inject()` (Isar is opened there with every `stored_*` schema).
- Locator: the global `sl` (`lib/src/core/services/service_locator/`, a GetIt wrapper). Its only safe registration is `sl.safeRegisterSingleton<T>(…)`; services, data sources and repositories use it.
- Constructor injection everywhere else; pages provide cubits with `BlocProvider(create: (_) => sl.get<T>())` or build them from injected repositories.

### Localisation
- Applies to: `lib/src/core/l10n/**`, `lib/src/*/ui/**`
- Sources: `lib/src/core/l10n/app_en.arb` (template), `app_ka.arb`; config `l10n.yaml`; class `FuzzzySealLocalizations`, read as `context.fuzzzySealLocalizations.<key>` (outside a widget: `currentContextLocalization`). Georgian is required for every key.
- Regenerate: `fvm flutter gen-l10n`
- Regenerated by tool, never hand-edited: `lib/src/core/l10n/generated_localizations/fuzzzy_seal_localizations.dart`, `fuzzzy_seal_localizations_en.dart`, `fuzzzy_seal_localizations_ka.dart`
- `./loc.sh` is broken (it sources a missing `scripts/runner.sh`): edit both `.arb` files by hand.

### Rust core and bridge
- Applies to: `rust/**`, `lib/rust_bridge/**`, `lib/src/core/encryption_services/**`, `lib/src/app/initializer.dart`, `test/helpers/**`, `test/src/core/**`
- Crate `rust/fuzzy_crypto_core` (toolchain 1.98.1 from its `rust-toolchain.toml`: run cargo from the crate folder, never with `--manifest-path` from the root, which picks the default toolchain). Every build and test is `--locked`.
- Order of work: edit `src/api/*.rs` → `cargo test --locked` → `flutter_rust_bridge_codegen generate` (from the repo root, reads `flutter_rust_bridge.yaml`) → `fvm flutter analyze` → commit with the generated files.
- Regenerated by tool, never hand-edited: `lib/rust_bridge/frb_generated.dart`, `lib/rust_bridge/frb_generated.io.dart`, `lib/rust_bridge/frb_generated.web.dart`, `lib/rust_bridge/error.dart`, `lib/rust_bridge/api/core.dart`, `files.dart`, `formats.dart`, `health.dart`, `pairing.dart`, `passwords.dart`, `vault.dart`, `rust/fuzzy_crypto_core/src/frb_generated.rs`
- Regenerate: `flutter_rust_bridge_codegen generate`
- `fvm flutter test` loads `rust/fuzzy_crypto_core/target/release/libfuzzy_crypto_core.{dylib,so}`: rebuild it (`cargo build --release --locked`) after any Rust change. A test that touches the core calls `initCryptoCoreForTests()` (`test/helpers/crypto_core_test_init.dart`) in `setUpAll`.
- `CoreError` is mirrored exhaustively by `CryptoCoreFailureType` (`lib/src/core/encryption_services/crypto_core_service/components/crypto_core_failure_type.dart`); a new error variant changes both in one commit.

### Storage (Isar)
- Applies to: `lib/src/*/storage/**`, `lib/src/core/dependency_injection.dart`
- Models are `storage/storage_models/stored_*.dart` with committed `.g.dart` twins; local data sources in `storage/local_data_sources/`.
- `./buildrunner.sh` is broken and `build_runner` / `isar_generator` are not in the pubspec: a changed model is regenerated in a scratch package outside the repo (`isar ^3.1.0+1`, `build_runner ^2.4.0`, `isar_generator ^3.1.0+1`), after proving the unchanged model regenerates byte-identical; then the schema goes into `Isar.open`.

### Tests and harness
- Applies to: `test/**`
- Layout: `test/src/<feature>/<layer>/…` mirroring `lib/src/` (`bloc/<name>_cubit/`, `data/repositories/`, `ui/pages/<page>/`); platform manifest tests in `test/platform/`.
- Doubles: `mocktail` (`class Mock<Name> extends Mock implements <Type> {}`); cubits with `bloc_test`. A test that needs `sl` registers with `sl.safeRegisterSingleton<T>(…)` in `setUp` and calls `sl.unregister<T>()` in `tearDown`.
- Widget harness: `MaterialApp(theme: FuzzzyTheme.build(inkPack, FuzzzySkin.night), localizationsDelegates: FuzzzySealLocalizations.localizationsDelegates, …)` inside the test file; there is no shared pump helper.
- Time: `fake_async` or `Completer` ordering, never the wall clock (FZ-TEST-CLOCK-01); `fake_async` arrives only through `flutter_test` (not a direct dev dependency yet).

### Failures
- Applies to: `lib/src/*/data/**`, `lib/src/*/storage/**`, `lib/src/*/bloc/**`, `lib/src/core/encryption_services/**`, `lib/src/core/error_handling/**`
- There is no HTTP layer. Failures come from the core (`CryptoCoreFailure(CryptoCoreFailureType)`: `unsupportedFormat`, `invalidSignature`, `invitationAlreadyUsed`, `wrongChat`, `replay`, `tooOld`, `corrupt`, `wrongPassword`, `storeLocked`, `unknownChat`, `io`, `cancelled`, `internal`) and from local storage.
- UI failure types live in `lib/src/core/error_handling/ui_failures/` (`chat_creation_failure`, `connected_chat_failure`, `file_processing_failure`, `chat_archive_export_failure`); `DefaultFailure` in `lib/src/core/error_handling/default_failure.dart`.

### CI
